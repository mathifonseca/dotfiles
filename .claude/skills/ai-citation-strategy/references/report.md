# Become the record AI assistants cite

A site becomes the source that ChatGPT, Claude, Perplexity, Gemini, Google's AI Overviews and AI Mode, Copilot and Siri cite in the same way it becomes a source search engines trust: **it gets into the few search indexes those assistants draw on (Google, Bing, Brave and the AI companies' own), and it puts complete, current and correct facts into server-rendered HTML that a fetcher can read without running JavaScript.** The assistant operators' own guidance adds little beyond original content, clear structure and accessible markup, and the best evidence found **no citation lift from adding schema, zero requests in a month for 97% of published llms.txt files, and gains in only 3 of 54 cases for "GEO" rewriting**. agentready.org, a vendor proposal from Ora and Vercel, is right where it agrees with that evidence (don't block agents, put the answer in the first HTML response, return real status codes), while its newer files and protocols mostly serve developer tools rather than the people who ask assistants where to go. Places and dated events offer an unusually wide opening: assistants fail mainly by leaving facts out or repeating last year's, the place platforms they lean on handle free seasonal events poorly, and the real questions ("which markets are open on 26 December?") compare many places at once, which no single organiser page answers. One strategy fits both Mercaditos and The Cultural Club: be reachable and readable, be the most complete and honestly dated record of the niche in every language people ask in, push each change to the indexes, earn mentions where assistants already look, add a small read-only MCP server once the basics hold, and measure mention rates and date accuracy rather than rankings. Mercaditos fails several of the basics today (unknown URLs return HTTP 200, crawlers almost certainly see only the English version, and every sitemap date is the time the sitemap was generated), so its first work is plumbing, not protocols.

## agentready.org gets the basics right and oversells the extras

agentready.org calls itself "the open standard for agent readiness", but its own repository describes a "proposed standard" written by ora.ai and Vercel, MIT-licensed and holding **38 GitHub stars** on the day of this research ([GitHub](https://github.com/agentready-org/standard)). No standards body stands behind it. Version 2.0, from October 2026, sets 24 requirements in three groups (Find, Read and Act) and **four MUSTs: do not block agents or crawlers, put the answer in the initial HTML, return real HTTP status codes, and, only for products that agents are expected to act on, ship an MCP server or a command-line tool** ([spec](https://github.com/agentready-org/standard/blob/main/spec/spec.md)). The spec has no score by design; grades come from Ora's scanner and from partner "rankers" such as Vercel's is-agentic.com ([agentready.org](https://www.agentready.org/)). It also moves fast, with three versions in six months, identifiers retired twice and strengths reassigned along the way ([changelog](https://github.com/agentready-org/standard/blob/main/CHANGELOG.md)), so a claim of conformance means little without a version number.

The strength tags rest on Ora's own studies of agent "harnesses", meaning Claude and GPT models running inside agent SDKs and coding tools, mostly against software and SaaS sites. The cleanest is a controlled experiment in which one documentation site was served in 19 configurations and probed 190 times: **only two changes stopped agents from retrieving the answer, hiding it behind JavaScript and answering agent user agents with a 403** ([Ora](https://ora.ai/blog/agentready-open-standard)). A larger preprint followed 37,927 agent journeys about 1,056 businesses. Answers about "agent-ready" businesses were built from the business's own pages 78% of the time against 56% for the rest, and answers built from the wider web were 3.7 times as likely to contain none of the requested facts; in the authors' words, "the main problem is omission rather than fabrication" ([arXiv](https://arxiv.org/abs/2609.34951)). Two caveats limit how far this transfers. The readiness score is Ora's own product, and the four harnesses (the Claude Agent SDK, Claude Code, OpenClaw and Ora's "eve") are developer agents, not ChatGPT search, Gemini, Perplexity or Copilot, which retrieve through their own indexes ([Ora](https://ora.ai/blog/ax-is-the-new-aeo)). Ora is candid about what it has not tested: on connectors and registries, "We haven't measured this, so we're not claiming it."

Set beside the other checklists of 2026 (Cloudflare's isitagentready.com, Vercel and Ora's is-agentic.com, Mintlify's documentation score, Lighthouse's experimental "Agentic Browsing" audit) and beside the guidance of the companies that run assistants, agentready exposes a clear fault line. **Nearly everyone agrees on two things: don't block agents, and deliver content as server-rendered text.** Most also back sitemaps, real status codes and JSON-LD that repeats the visible facts. What is contested is a new layer of files: llms.txt, Markdown mirrors, agent-skill indexes, AI catalogs, MCP server cards and Content Signals. It is promoted mainly by infrastructure and tool vendors whose products map onto the checks, and apart from llms.txt it barely exists on the web: across the 200,000 most-visited domains, 3.9% pass Cloudflare's Markdown check and fewer than 15 publish MCP server cards or API catalogs ([Cloudflare](https://blog.cloudflare.com/agent-readiness/)). The assistant operators do not endorse it. Google Search says "you don't need to create new machine readable files, AI text files, markup, or Markdown to appear in Google Search" ([Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)), and Google's John Mueller compared llms.txt to the keywords meta tag ([SEJ](https://www.searchenginejournal.com/googles-llms-txt-guidance-depends-on-which-product-you-ask/575431/)). Microsoft's advice is clear headings, schema, and no facts hidden in tabs, images or PDFs ([Microsoft](https://about.ads.microsoft.com/en/blog/post/october-2025/optimizing-your-content-for-inclusion-in-ai-search-answers)). Google's Chrome team and OpenAI stress something agentready omits entirely, accessibility: Lighthouse states that **"agents rely on the accessibility tree as their primary data model"** ([Chrome](https://developer.chrome.com/docs/lighthouse/agentic-browsing)), and OpenAI told publishers that its Atlas browser read ARIA roles and labels ([OpenAI](https://help.openai.com/en/articles/12627856-publishers-and-developers-faq)). Both camps are right, about different agents. Fetch tools read text; browser agents read the accessibility tree, the DOM and screenshots. A site that serves both needs server-rendered text and an accessible interface, and no single scanner checks both.

agentready says nothing about places, events, opening hours or dated content ([agentready.org](https://www.agentready.org/)). For a content site its Act group does not apply under its own conformance rule, which leaves a short, well-supported core: access, initial HTML, status codes, a sitemap, JSON-LD whose facts are repeated as visible text (because "most agents read a page's text, not its `<script>` elements"), prices as text (agents' answers were 60% accurate from first-party pages against 37% from elsewhere) and one canonical, current page per thing ([spec](https://github.com/agentready-org/standard/blob/main/spec/spec.md)). The scanners are worth running as delivery checklists on their content-site presets, never as targets; a composite score is "the wrong thing to optimize for" and "measures delivery, not message" ([SEJ](https://www.searchenginejournal.com/all-you-need-to-know-about-cloudflares-agent-readiness-score/)). A Vercel-hosted site such as Mercaditos should expect nudges toward the full checklist, since Vercel co-wrote it and runs is-agentic, and only the core has evidence from the assistant side.

## A few search indexes and JavaScript-blind fetchers decide who gets read

Assistants do not crawl the web afresh for each answer. They retrieve candidates from a search index and sometimes fetch a page live while answering. **Google's AI Overviews and AI Mode use the ordinary Search index and ranking systems, and a page only has to be "indexed and eligible to be shown in Google Search with a snippet"** ([Google](https://developers.google.com/search/docs/appearance/ai-features)). Copilot is grounded in Bing, whose rewritten guidelines now cover Copilot citations ([SEJ](https://www.searchenginejournal.com/bing-adds-geo-to-official-guidelines-expands-ai-abuse-definitions/568442/)). Ahrefs traced 88% of ChatGPT's citations to general web search results ([SEJ/Ahrefs](https://www.searchenginejournal.com/ai-search-myths-debunked-ahrefs-spa/584393/)). Claude's web search reportedly runs on Brave: vendor tests found **79–88% of the URLs Claude retrieved in Brave's top 10**, against 46% in Google's ([CompleteSEO](https://completeseo.com/claude-web-search-runs-on-brave/); [Xponent21](https://xponent21.com/insights/claude-web-search-brave-turbopuffer/)). The base layer of "AI visibility" is therefore ordinary indexing in Google, Bing and Brave, plus admission for each operator's own bots. Brave's crawler was outside this research, so the practical check there is whether the site's pages show up in Brave Search. The operators' bot pages give the rest of the map ([OpenAI](https://developers.openai.com/api/docs/bots); [Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler); [Perplexity](https://docs.perplexity.ai/guides/bots); [Google](https://developers.google.com/search/docs/crawling-indexing/google-common-crawlers); [Apple](https://support.apple.com/en-us/119829); [Meta](https://developers.facebook.com/docs/sharing/webmasters/web-crawlers)), and the new Siri reportedly runs on Google's Gemini models ([Let's Data Science](https://letsdatascience.com/news/apple-launches-gemini-powered-siri-raises-search-questions-3c3c18b2)).

| Assistant | Index behind its answers | Bots to admit for answers | Training-only control |
|---|---|---|---|
| Google AI Overviews, AI Mode | Google Search | Googlebot | None needed; Google-Extended does not affect Search |
| Gemini app | Google Search (grounding) | Googlebot, Google's user-triggered fetchers | Google-Extended, which also ends Gemini-app grounding |
| ChatGPT | OpenAI's own index plus third-party providers | OAI-SearchBot, ChatGPT-User | GPTBot |
| Claude | Brave (reported) plus Anthropic's crawler | Claude-SearchBot, Claude-User | ClaudeBot |
| Perplexity | Its own index | PerplexityBot, Perplexity-User | None; Perplexity says it does not train |
| Copilot | Bing | Bingbot | No token; the NOARCHIVE tag also removes Copilot use |
| Siri, Spotlight | Applebot's crawl; new Siri reportedly on Gemini | Applebot | Applebot-Extended |
| Meta AI | Its own index plus Bing and Google (reported) | Meta-WebIndexer, Meta-ExternalFetcher | Meta-ExternalAgent, which also indexes |

Every operator now splits its bots by purpose: training, search indexing, fetches triggered by a user's question, and browsing agents. That lets a site opt out of training without leaving the answers of OpenAI, Anthropic or Apple. Google is the exception that catches people out: Google-Extended does not touch Search or AI Overviews, but **it does control grounding in the Gemini app, so blocking it removes a site from Gemini's answers**. Live fetchers are not reliably bound by robots.txt. OpenAI says its rules "may not apply" to ChatGPT-User, Perplexity says Perplexity-User "generally ignores" them, and TollBit found about 15% of AI fetchers on European sites reaching disallowed URLs ([SEJ](https://www.searchenginejournal.com/openai-says-robots-txt-may-not-apply-to-chatgpts-fetch-bot/)). For a site that wants to be the source this is moot, because live fetchers are the bots that produce citations. The quiet way to disappear is the CDN. **From 15 September 2026, Cloudflare blocks Training and Agent bots by default on ad-showing pages of new domains, and treats multi-purpose crawlers such as Googlebot, Bingbot and Applebot under the strictest matching rule, so blocking "Training" can remove a site from Google, Bing and Apple** ([Cloudflare](https://blog.cloudflare.com/content-independence-day-ai-options/)). Vercel blocks nothing by default and lets verified bots skip its Bot Protection, but switching its AI Bots ruleset to "Deny" blocks the search crawlers and live fetchers along with the trainers ([Vercel](https://vercel.com/docs/bot-management)).

JavaScript is the second filter. **Only Googlebot and Applebot are documented to render it.** The last large log study found that the crawlers of OpenAI, Anthropic, Meta, ByteDance and Perplexity download scripts but never run them ([Vercel/MERJ](https://vercel.com/blog/the-rise-of-the-ai-crawler)), and an October 2025 test found Gemini the only live fetcher that rendered JavaScript ([searchVIU](https://www.searchviu.com/en/schema-markup-and-ai-in-2025-what-chatgpt-claude-perplexity-gemini-really-see/)). Map pins, client-fetched lists and popups are invisible to most assistants. Server rendering is necessary but not sufficient on Next.js 16. AI crawlers are not on Next's list of "HTML-limited" bots ([Next.js](https://github.com/vercel/next.js/blob/canary/packages/next/src/shared/lib/router/utils/html-bots.ts)), so they get the streaming version of a page, in which Suspense content arrives in hidden blocks at the end of the document and metadata can be appended to `<body>` ([Next.js](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#streaming-metadata)). When a page calls `notFound()` after streaming has begun, "Next.js cannot go back and change the status to 404" and injects a noindex tag instead ([Next.js](https://nextjs.org/docs/app/guides/streaming)). The research team's own requests to mercaditos.app on 22 October 2026 showed the problem in practice: a 650 KB page whose Suspense content arrives in six hidden blocks at the end, and unknown paths answered with HTTP 200 plus noindex ([mercaditos.app](https://mercaditos.app/berlin); [unknown city](https://mercaditos.app/this-city-does-not-exist)). No source establishes whether AI fetchers keep hidden Suspense blocks when they convert HTML to text, or how much of a long page they read, so the safe rule is to render primary facts and metadata early and outside late-streamed boundaries, and to decide status codes before streaming starts.

Freshness and language are crawl problems too. Only Google and Bing document how they use sitemaps; Bing wants `lastmod` to be "the true last modification time of the page content" and ignores `changefreq` and `priority` ([Bing](https://blogs.bing.com/webmaster/July-2025/Keeping-Content-Discoverable-with-Sitemaps-in-AI-Powered-Search)). IndexNow pushes changes instantly to Bing, Yandex, Seznam, Naver, Yep, the Internet Archive and Amazon, but not to Google ([IndexNow](https://www.indexnow.org/searchengines.json)). No AI company says how often its index refreshes. A vendor study saw GPTBot reach new pages on an established domain within 14 minutes and all bots together reach 43% of them within 24 hours ([Presenc](https://presenc.ai/research/how-fast-ai-crawlers-index-new-pages)), while a page on a brand-new domain was still absent from ChatGPT search after three days ([Metehan Yesilyurt](https://metehan.ai/blog/how-to-submit-index-your-page-on-searchgpt-an-experiement-results)). Season pages therefore need to be live and linked weeks before the season starts. On language, **Googlebot sends no `Accept-Language` header and crawls mainly from US addresses; Google warns that when one URL changes language by visitor it "might not crawl, index, or rank all your content for different locales", and its fix is a separate URL per locale annotated with hreflang** ([Google](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)). The 2024 log study found every measured AI crawler running from US data centres as well.

## Markup serves Search, llms.txt goes unread, and MCP is the one protocol bet

Structured data still earns Google rich results. Event, Local business, Organization and Breadcrumb remain supported, and Event results run for German pages in Germany and Spanish pages in Spain, with Catalan absent from the list ([Google](https://developers.google.com/search/docs/appearance/structured-data/event)). Bing says schema helps its language models understand content ([Search Engine Land](https://searchengineland.com/microsoft-bing-copilot-use-schema-for-its-llms-453455)). But Google says "there's no special schema.org structured data that you need to add" for its AI features, and the one controlled test found no lift: **Ahrefs compared 1,885 pages that added JSON-LD with about 4,000 matched controls, and ChatGPT citations rose 2.2% and AI Mode 2.4%, both indistinguishable from zero, while AI Overviews fell 4.6%** ([Ahrefs](https://ahrefs.com/blog/schema-ai-citations/)). Live fetchers mostly treat markup as text, if they read it at all. In a one-page test no assistant extracted a price that existed only in JSON-LD ([searchVIU](https://www.searchviu.com/en/schema-markup-and-ai-in-2025-what-chatgpt-claude-perplexity-gemini-really-see/)), and ChatGPT and Perplexity read a made-up address inside schema as ordinary page text ([Search Engine Roundtable](https://seroundtable.com/chatgpt-perplexity-structured-data-text-40862.html)). JSON-LD is a signal to search indexes that restates facts already visible on the page. It is still worth generating for Search, and Event markup has fields for exactly the changes dated content suffers: an `eventStatus` of cancelled, postponed or rescheduled, the original `startDate` kept, and `previousStartDate`. FAQ markup is not worth adding, because Google retired FAQ rich results in May 2026 ([Google](https://developers.google.com/search/updates)).

llms.txt, proposed in September 2024 as a Markdown index of a site ([llmstxt.org](https://llmstxt.org/)), is the clearest case of a file nobody reads. **Ahrefs examined 137,210 domains: 28% published one, and 97% of those files received zero requests in May 2026**, with most remaining fetches coming from coding tools such as Claude Code and occasional GPTBot visits ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)). SE Ranking found no correlation with AI citations across about 300,000 domains ([SEJ](https://www.searchenginejournal.com/llms-txt-shows-no-clear-effect-on-ai-citations-based-on-300k-domains/561542/)), Google Search ignores the file, and Mueller called it "purely speculative" in June 2026 ([TechWyse](https://www.techwyse.com/news/ai-search/google-john-mueller-llms-txt-speculative-webmcp-ai-agents)). Markdown versions of pages tell the same story. Claude Code, Cursor and OpenCode ask for `text/markdown`, while OpenAI Codex, Gemini CLI, GitHub Copilot and Windsurf do not ([Checkly](https://www.checklyhq.com/blog/state-of-ai-agent-content-negotation/)). In two weeks of one commercial site's logs, **the fetchers acting for ChatGPT, Claude and Perplexity users took HTML more than 13,000 times and Markdown once** ([GoodBarber](https://www.goodbarber.com/blog/do-ai-agents-read-markdown-what-two-weeks-of-our-own-server-logs-say-a1622/)). Even agentready demoted Markdown to optional, because "format did not determine task success".

The Model Context Protocol (MCP) is different: it is the one agent protocol with real support in mainstream assistants. **Claude lets users on every plan add a remote MCP server by URL, including one that needs no sign-in (the free plan allows one)** ([Claude](https://claude.com/docs/connectors/custom/remote-mcp)). ChatGPT's apps, reportedly renamed "plugins" in July 2026, are built on MCP and reviewed into a directory that at launch excluded the EEA, Switzerland and the UK ([OpenAI](https://openai.com/index/introducing-apps-in-chatgpt/); [OpenAI Help](https://help.openai.com/en/articles/11487775-apps-in-chatgpt)), and Gemini supports MCP in its enterprise products and only partly in the consumer app ([Progressive Robot](https://www.progressiverobot.com/2026/09/06/gemini-business-custom-mcp-server-connections/)). The project reported 97 million monthly SDK downloads in December 2025 ([MCP](https://blog.modelcontextprotocol.io/tags/aaif/)), and the official registry held about 43,000 servers in October 2026 ([gravity.fast](https://gravity.fast/data/mcp-adoption-statistics/)). Booking.com and Expedia launched ChatGPT apps in 2025, and Ticketmaster followed in April 2026 ([OpenAI](https://openai.com/index/introducing-apps-in-chatgpt/); [Music Business Worldwide](https://www.musicbusinessworldwide.com/ticketmaster-launches-app-within-chatgpt-bringing-event-discovery-to-openais-chatbot/)). But **no evidence shows any assistant discovering a small site's server on its own**: users add servers by hand or through a reviewed directory, the `.well-known` discovery path is still moving between drafts ([MCP SEP-2127](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2127)), and nobody has published usage figures for a content or events server. MCP's distinctive value for dated events is that it answers from the live database ("which markets are open on 24 December after 18:00?"), while answers built from an index can be days old. It is a cheap option to take once the HTML is right: a read-only server with no sign-in, whose every result carries the page's canonical URL so the assistant can cite it.

The rest of the agent stack has no consumer audience yet. NLWeb, launched by Microsoft in 2025 with Eventbrite and Tripadvisor among its named partners, has "no public count" of deployments and no evidence that ChatGPT, Claude, Copilot or Gemini query its `/ask` endpoints ([Presenc](https://presenc.ai/research/nlweb-adoption-2026)). WebMCP, which lets a page declare its forms and actions as tools for browser agents, has been a Chrome origin trial since Chrome 149, with Gemini in Chrome support described in May 2026 as "coming soon" ([Chrome](https://developer.chrome.com/blog/ai-webmcp-origin-trial); [PPC Land](https://ppc.land/chrome-149-origin-trial-puts-webmcp-in-developers-hands-at-last/)). A2A links enterprise agents to each other, and the commerce protocols (ACP, UCP, x402) matter only to a site that sells tickets. Content-use signals such as Cloudflare's Content Signals and the IETF's draft AI preferences express wishes that no assistant has publicly committed to honour ([Cloudflare](https://blog.cloudflare.com/content-signals-policy/); [IETF](https://datatracker.ietf.org/wg/aipref/documents/)). iCalendar and RSS feeds serve people and partners well, but no platform documents assistants subscribing to them. The churn is itself a warning: ChatGPT plugins and their manifest file ended in 2024 ([AIWiki](https://www.aiwiki.ai/wiki/chatgpt_plugins/raw)), OpenAI shut its Atlas browser on 9 August 2026 ([OpenAI](https://help.openai.com/en/articles/20001371)), and agentready has retired its own identifiers twice.

| Item | Who demonstrably uses it, October 2026 | Strongest evidence | Verdict |
|---|---|---|---|
| Facts as visible text in server-rendered HTML | Every crawler, live fetcher and browser agent | Platform docs; Ora's controlled test; fetch tests | Foundation |
| Admitting search crawlers and live fetchers | Every assistant | Operators' bot documentation | Foundation |
| Real status codes, canonical URLs, one URL per language | Google, Bing, every fetcher | Google docs; agentready MUST | Foundation |
| Accessible, semantic controls | Browser agents | OpenAI and Google docs | Do |
| Honest `lastmod`, IndexNow pings | Google; Bing and Copilot | Bing and Google docs | Do |
| JSON-LD that repeats visible facts | Google rich results, Bing | Ahrefs: no AI-citation lift | Do, for Search |
| Read-only remote MCP server | Claude, ChatGPT, developer tools | Host docs; no usage data | Small bet after the basics |
| llms.txt | Coding agents, occasional GPTBot | Ahrefs: 97% never requested | Optional, generated live |
| Markdown mirrors | Coding agents, some crawlers | One Markdown fetch per 13,000 HTML | Skip unless free |
| iCalendar and RSS feeds | People and aggregators | No agent evidence | For humans |
| WebMCP | Chrome origin trial | Docs only | Watch |
| NLWeb, A2A, AI Catalog, agent skills, Content Signals | No consumer assistant | None | Skip |
| ACP, UCP, x402 | Commerce agents | Vendor tests | Only if selling tickets |

## Relevance, explicit facts and real updates beat every GEO trick

The famous claim that "generative engine optimization" lifts visibility by up to 40% comes from a 2023 lab set-up: a page already sitting among five documents fed to GPT-3.5, scored by its share of the answer's words and by an LLM judge ([arXiv](https://arxiv.org/abs/2311.09735)). A July 2026 critical survey of about 45 studies lists that claim as **"rejected as a general claim"** ([Martinez](https://arxiv.org/html/2607.14035v1)). At scale the tricks fade. C-SEO Bench (NeurIPS 2025) found only 3 of 54 method-and-domain combinations significantly positive, concluded that "traditional SEO strategies... are significantly more effective", and saw gains shrink as more sites adopted the methods ([arXiv](https://arxiv.org/abs/2506.11097)). A full-pipeline test found that rewriting a page's body lowered its presence at retrieval, reranking and citation ([Martinez](https://arxiv.org/html/2607.14035v1)). The survey's confidence table is the best summary of the field: high confidence that relevance and position drive citation, low confidence that any white-hat content tactic durably lifts discoverability across engines.

What helps is narrower and plainer. A SIGIR 2026 study of 252,000 controlled two-document trials across six models found **topical relevance and position the biggest drivers of being cited first, found that "explicit price information and a recent timestamp" help "consistently", and found that "formatting-only edits have little impact"** ([arXiv](https://arxiv.org/abs/2605.25517)). Placement matters: of 18,012 ChatGPT citations, 44.2% came from the first 30% of a page's text ([Growth Memo](https://www.growth-memo.com/i/188121887/3-entity-richness)), which matches Bing's advice to state essential facts near the top and give each URL one topic ([SEJ](https://www.searchenginejournal.com/bing-adds-geo-to-official-guidelines-expands-ai-abuse-definitions/568442/)). Freshness counts as real updates, not new URLs. **75% of the pages ChatGPT, Gemini and Perplexity cited had been updated within a year, though only 42% had been published within one, and more than a quarter of the "fresh" cited pages were old URLs updated in place** ([Seer](https://www.seerinteractive.com/insights/study-content-recencys-impact-on-ai-visibility-in-2026)). That argues for one durable URL per market or venue, updated each edition, rather than a new URL each year, and Google warns against bumping dates without real edits ([Google](https://developers.google.com/search/blog/2019/03/help-google-search-know-best-date-for)).

Ranking still gates citation, but the gate has widened. The share of AI Overview citations taken from top-10 pages fell from 76% in mid-2025 to about 38% in early 2026 in Ahrefs' data, measured with a changed parser ([Ahrefs](https://ahrefs.com/blog/ai-overview-citations-top-10/)), and an academic audit put 53% of cited domains outside the organic top 10 ([arXiv](https://arxiv.org/abs/2510.11560)). Ahrefs points to "query fan-out", the related sub-queries Google says its models generate ([Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)). A page that answers a sub-question precisely ("are Berlin's markets open on 24 December?") can therefore be cited without ranking for "Berlin Christmas markets".

Off-site signals count as mentions far more than as links. Across about 75,000 brands, **YouTube mentions (about 0.74) and branded web mentions (0.66–0.71) correlated with AI visibility far more strongly than backlinks (0.19–0.24)** ([SEJ/Ahrefs](https://www.searchenginejournal.com/ai-search-myths-debunked-ahrefs-spa/584393/)), and GPT-based search drew 69–92% of its citations from third-party "earned" media, against 32–54% for Google ([arXiv](https://arxiv.org/html/2509.08919)). Perplexity leans hardest on Reddit and review platforms such as Yelp and Tripadvisor ([Profound](https://www.tryprofound.com/blog/ai-platform-citation-patterns)). Being known is not being surfaced: ChatGPT recognised 99.4% of startups when they were named, but surfaced only 3.32% of them in open discovery questions ([Martinez](https://arxiv.org/html/2607.14035v1)). One finding favours aggregators. Self-promotional "best X" lists are often cited without their publisher being the one recommended (69% of 323 citations in a sample of business-to-business queries, [Lily Ray](https://lilyraynyc.substack.com/p/why-calling-yourself-the-best-could)), but a guide to other people's markets wants exactly that outcome: to be the cited list. These studies cover large brands and product categories, none covers small, local or seasonal sites, and nearly all industry figures come from vendors that sell visibility tools.

The popular content claims fare no better than the files. **Google says not to chunk pages or write specially for AI** ([Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)), and C-SEO Bench found such rewriting "largely ineffective" ([arXiv](https://arxiv.org/abs/2506.11097)). FAQ blocks have no controlled study behind them and earn no rich result. Author bios have only vendor claims without methods. Seeding Reddit chases a source whose share of ChatGPT responses fell from about 60% to about 10% within weeks in 2025 ([Semrush](https://www.semrush.com/blog/most-cited-domains-ai/)), while Google discounts inauthentic mentions and Bing now classes "artificially engineered language" and prompt injection as abuse ([SEJ](https://www.searchenginejournal.com/bing-adds-geo-to-official-guidelines-expands-ai-abuse-definitions/568442/)). No platform sells organic citations; Google says "no third-party tool has access to our internal ranking or AI systems" ([Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)). Two popular warnings are myths in the other direction: blocking Google-Extended does not remove a site from AI Overviews ([Google](https://developers.google.com/search/docs/crawling-indexing/google-common-crawlers)), and SEO is not dead, since Google's AI features retrieve through its core ranking systems.

Language and volatility shape all of this. **The language of a question predicts the language of the cited page: AI Overviews cited same-language pages for 85% of non-English prompts and ChatGPT for 70%** ([Temso](https://www.temso.ai/data/-Lost-in-Translation-How-AI-Models-Handle-Local-Language-Sources)), and open models preferentially cite English sources for English questions ([arXiv](https://arxiv.org/abs/2509.13930)). An English question about Berlin will mostly be answered from English pages, which leaves berlin.de and other German sources under-cited and gives an accurate English version of German facts real value, while a German version competes head-on with them. No study has tested English questions about non-English places directly, so this is a strong inference rather than a measurement. Nothing is stable either. After a model change on 22–23 May 2026, German-language ChatGPT's daily citation pattern shifted 47% instead of the usual 1–2%: welt.de rose 99%, faz.net 124% and openstreetmap.org 83%, while Tripadvisor fell 53% ([SEJ/SISTRIX](https://www.searchenginejournal.com/chatgpt-citations-changed-after-gpt-5-5-sistrix-data-shows/577694/)). Local sources can gain on global aggregators overnight, and lose the gain the same way.

## For places and events, stale and missing dates are the failure to beat

Facts about places reach assistants through five layers: the model's memory (stale by design), place-of-record platforms, ticketing partners, web search indexes, and first-party or editorial pages. Google's assistants ground place questions in Maps, which covers "over 250 million places" with hours and reviews ([Google](https://ai.google.dev/gemini-api/docs/maps-grounding)). In BrightLocal's 2026 study of the US, UK and Australia, **Google Business Profile supplied about two-thirds of local-business citations in AI Overviews, and Yelp about 61% of ChatGPT's** ([BrightLocal](https://www.brightlocal.com/resources/ai-directory-sources/)), and OpenAI now licenses Yelp's data ([Axios](https://finance.yahoo.com/media-advertising/articles/exclusive-yelp-deal-pushes-local-130005436.html)). Ticketed events have their own pipes, with Ticketmaster and SeatGeek apps in ChatGPT and booking agents in AI Mode in the US ([Tom's Guide](https://www.tomsguide.com/ai/googles-ai-mode-now-books-your-event-tickets-and-beauty-appointments-for-you)). A free Christmas market has none of these. It sells no tickets, rarely has a claimed profile, and Google Maps refuses "temporary, one-time events", accepting seasonal businesses only if they re-open in the same place ([Google](https://support.google.com/maps/answer/2642650)). That is where assistants fall back on web pages, and where a niche site can become the source.

The documented failures sit in exactly this gap. An AI Overview insisted the year was 2024 ([Android Authority](https://www.androidauthority.com/google-search-ai-overview-doesnt-know-the-year-3561764/)). AI travel advice reportedly stranded a couple on a Japanese mountain with a wrong last-ropeway time and sent tourists in Peru looking for a canyon that does not exist ([AI Incident Database](https://incidentdatabase.ai/cite/1636)), and ChatGPT recommended a Liverpool market for Christmas Eve when it ran for one weekend in early December ([EM360Tech](https://em360tech.com/tech-article/chatgpt-plan-holidays)). In 2025 Baidu's AI search repeated, and Grok echoed, a false claim that Germany had cancelled many Christmas markets, which tourism offices then refuted ([Annie Lab](https://annielab.org/2025/11/14/analysis-most-german-christmas-markets-to-open-as-planned-in-2025/)), and AI-made posts sent visitors to a Buckingham Palace market that never existed ([CP24](https://www.cp24.com/news/2025/11/21/tourists-baffled-by-ai-buckingham-palace-christmas-market)). Audits show the scale: **45% of news answers from ChatGPT, Copilot, Gemini and Perplexity had a significant issue, with sourcing the largest category** ([EBU](https://www.ebu.ch/research/open/report/news-integrity-in-ai-assistants)), and 11% of the claims in AI Overviews were not supported by the pages they cited, with omission the dominant failure ([arXiv](https://arxiv.org/abs/2605.14021)). No study has measured how often assistants get event dates or seasonal hours wrong; a site that measures it will hold the first numbers.

Recency bias cuts both ways. In a lab test, giving passages newer dates moved LLM rerankers' top-10 mean year forward by up to 4.78 years and flipped up to 25% of their choices between equally relevant passages ([arXiv](https://arxiv.org/abs/2509.11353v1)). A page that states this year's dates beats last year's page with the same name and venue, and **a page that says "2026" before the organisers have confirmed anything will be believed too**. "Dates not announced yet" is therefore a fact worth stating, and so is "closed on 25 December", because negative facts decide plans and most sources leave them implicit. No study shows engines rewarding provenance text as such; trust cues gave only small gains in the 252,000-trial study ([arXiv](https://arxiv.org/abs/2605.25517)). A specific "verified on" date still works as a recency signal, and a named source for each fact matches the survey's best-supported advice to publish "relevant, verifiable, dated, and properly attributed evidence" ([Martinez](https://arxiv.org/html/2607.14035v1)). Microsoft asks for content that is "current and consistent with authoritative sources" ([Search Engine World](https://www.searchengineworld.com/microsoft-shares-exact-signals-ai-uses-to-choose-content-for-search-answers)), so where a site disagrees with an organiser it should say why and link the organiser.

An aggregator does not win by restating the official page. For unbranded factual questions, first-party and local pages made up nearly 60% of citations in Yext's data ([Yext](https://www.businesswire.com/news/home/20251009106549/en/Yext-Research-86-of-AI-Citations-Come-from-Brand-Managed-Sources-Clarifying-How-Marketers-Can-Compete-in-the-AI-Search-Era)), and when AI spread the false cancellations, the corrections came from tourism offices ([Annie Lab](https://annielab.org/2025/11/14/analysis-most-german-christmas-markets-to-open-as-planned-in-2025/)). **An aggregator earns citations when it supplies what official pages lack: completeness across a whole city, comparisons across places ("open on 26 December", "free entry", "open late"), day-level hours with holiday exceptions, and versions in the languages visitors ask in.** The category winners that do appear, such as Cruise Critic as the most-cited domain in six of seven cruise-line reports ([Gradial](https://gradial.com/blog/travel-hospitality-geo-industry-research)), share one stable, continuously updated page per entity and first-hand evidence the official site lacks. No documented case shows a niche event site becoming its niche's cited source, so this is a hypothesis to test, not a result.

A places site also has to tend records it does not own. It may not claim Google Business Profiles for markets it does not run ([Google](https://support.google.com/business/answer/13763036)), but it can suggest edits such as holiday hours, add seasonal places that re-open at the same spot, and encourage organisers to claim their profiles. It can tag markets in OpenStreetMap's Christmas scheme, which already has fields for holiday exceptions and an `xmas:lastcheck` date ([OSM Wiki](https://wiki.openstreetmap.org/wiki/DE:Key:xmas:feature)), and create Wikidata items for markets backed by "serious and publicly available references" ([Wikidata](https://www.wikidata.org/wiki/Wikidata:Notability)). None of these is proven to reach assistants. They are cheap, and they keep the record consistent across the layers that assistants mix.

## Measure mention rates and date accuracy, not rankings or clicks

Visibility in AI answers and traffic from them are different things. **When a Google AI summary appeared, people clicked a traditional result in 8% of visits, against 15% without one** ([Pew](https://www.pewresearch.org/short-reads/2025/07/22/google-users-are-less-likely-to-click-on-links-when-an-ai-summary-appears-in-the-results/)), and a randomized field experiment found that AI Overviews cut organic clicks by about 38% ([SEJ](https://www.searchenginejournal.com/ai-overviews-cut-organic-clicks-38-field-study-finds/)). Being cited inside an AI Overview more than doubles click-through compared with not being cited, but stays well below the rate with no AI Overview at all ([Seer](https://www.seerinteractive.com/insights/aio-impact-on-google-ctr-2026-update)). Questions with "when" or "where", the core of a places site, trigger summaries 60% of the time ([Pew](https://www.pewresearch.org/short-reads/2025/07/22/google-users-are-less-likely-to-click-on-links-when-an-ai-summary-appears-in-the-results/)). Assistants themselves send only **about 0.3–1% of site visits** ([SE Ranking](https://seranking.com/blog/ai-traffic-research-study/); [Conductor](https://www.businesswire.com/news/home/20251113364791/en/Conductor-Unveils-2026-AEO-GEO-Benchmarks-Report-How-AI-Shapes-Brand-Visibility-in-a-Zero-Click-World)) while crawling far more than they refer: in July 2025 Anthropic made about 38,000 crawls per referred visit, OpenAI about 1,100 and Google about 5 ([Cloudflare](https://blog.cloudflare.com/ai-search-crawl-refer-ratio-on-radar)). The measures that matter are citations, mentions and the accuracy of what assistants say, with referrals as a side signal.

Five layers cover it, cheapest first. AI crawlers do not run JavaScript, so client-side analytics such as Umami cannot see them, and on Vercel's free Hobby plan the firewall and observability views keep only hours of history while log drains need the Pro plan at $0.50 per GB ([Vercel](https://vercel.com/docs/drains)). The cheapest durable log is a few lines in Next.js 16's `proxy.ts` that write bot hits to Postgres in the background with `event.waitUntil()` ([Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/proxy)), checked daily against the operators' published IP lists, because spoofing is common: 5.7% of traffic claiming to be AI crawlers was fake across HUMAN's network, and on one small site only 6 of 33 "AI assistant" visits were genuine ([HUMAN](https://humansecurity.com/learn/blog/ai-crawler-spoofing-chatgpt-mistral-perplexity/); [SEJ](https://searchenginejournal.com/my-ai-assistant-traffic-was-fake-the-googlebot-number-was-worse/580052/)). For clicks, only ChatGPT tags its links (`utm_source=chatgpt.com`), and clicks from AI Overviews and AI Mode cannot be told apart from organic Google. **Since the GPT-6 rollout around 9 October 2026, most ChatGPT clicks arrive without a referrer**, and for several days inline links also lost the UTM tag until a reported fix on 15 October. Adobe saw ChatGPT visits fall by about 31,000 a day on the same pages where Direct visits rose by about 26,000 ([SEJ](https://www.searchenginejournal.com/chatgpt-traffic-drop-appears-to-be-a-tracking-problem/593157/)). Umami's new "llm" channel keys only on the referrer, so a tagged ChatGPT visit without one is counted as Direct ([Umami](https://github.com/umami-software/umami/blob/master/src/queries/sql/getChannelMetrics.ts)); AI visits are the llm channel plus UTM-tagged visits with no referrer. Two free first-party reports arrived in 2026. Search Console's Generative AI report, worldwide since 31 August 2026, gives impressions in AI Overviews and AI Mode by page, country and device, with no clicks and no queries ([Google](https://support.google.com/webmasters/answer/16984139)). Bing's AI Performance report gives citations, cited pages, sampled "grounding queries" (the phrasings Copilot used to retrieve a page) and, since June 2026, Citation Share ([Bing](https://blogs.bing.com/webmaster/February-2026-284b440771373a5a245425a5d31a8ad6/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview); [Bing](https://blogs.bing.com/search/June-2026/New-AI-Visibility-Insights-in-Bing-Webmaster-Tools-Intents-Topics-Citation-Share-Compare)). One site counted about 48,000 Copilot citations and 14 clicks in three months ([Whole Whale](https://wholewhale.com/resources/bing-webmaster-analytics-for-ai-search-is-sobering/)). OpenAI and Perplexity offer publishers no dashboard.

The fourth layer is a prompt panel, and its design matters because answers barely repeat. **The same brand list came back in under 1 run in 100, while the share of runs mentioning a brand stayed steady** ([SparkToro](https://sparktoro.com/blog/new-research-ais-are-highly-inconsistent-when-recommending-brands-or-products-marketers-should-take-care-when-tracking-ai-visibility/)). In a study of 80 questions run 20 times each, 41–45% of the pages ChatGPT cited for a question appeared in only one run, and the API plus Google's results recovered only 26–28% of the pages the ChatGPT app cited ([arXiv](https://arxiv.org/abs/2610.15382)). The unit to report is "mentioned or cited in X% of N runs", per engine and language, at site level. A home-made panel on the OpenAI, Anthropic, Gemini and Perplexity APIs costs roughly $50 a month for 50 questions in three languages on four engines weekly, or about $150 with three repeats, by the research team's estimate from published prices ([OpenAI](https://developers.openai.com/api/docs/pricing); [Anthropic](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool); [Gemini](https://ai.google.dev/gemini-api/docs/pricing); [Perplexity](https://docs.perplexity.ai/guides/pricing.md)). It measures the APIs rather than the apps, and no API reproduces AI Overviews, so a cheap commercial tracker fills that gap: Otterly's $29 plan runs 15 prompts daily across ChatGPT, AI Overviews, Perplexity and Copilot ([Otterly](https://otterly.ai/pricing)). **The measure no vendor sells is accuracy**: extract the dates and hours from each answer and compare them with the site's own database. Anthropic's search tool returns the cited text and each page's age, which exposes last season's pages being cited.

| Layer | Question it answers | Tool | Rough cost |
|---|---|---|---|
| 1. Verified bot fetches, by class | Do search crawlers and live fetchers reach the current pages? | `proxy.ts` writing bot hits to Postgres, checked daily against published IP lists; a filtered log drain on Vercel Pro | About $0 on Hobby; cents a month on Pro, plus the plan |
| 2. AI referrals | Who clicks through from assistants, and to which pages? | Umami "llm" channel plus `utm_source=chatgpt.com` visits with no referrer | $0 |
| 3. First-party reports | How often do Google's AI features show the site, and Copilot cite it, for which phrasings? | Search Console Generative AI report; Bing AI Performance | $0 |
| 4. Prompt panel | How often is the site mentioned or cited per engine and language, and are its dates repeated correctly? | Script on the OpenAI, Anthropic, Gemini and Perplexity APIs with a city-level location, storing raw answers and model versions | Roughly $50–150 a month in season (estimate) |
| 5. Consumer-app sample | Do the real ChatGPT, AI Overviews, Perplexity and Copilot interfaces cite the site? | Otterly Lite, in season only | $29 a month |

Progress claims need discipline because the samples are small. Fix the prompts, engines and repeats before the season and leave them alone. At 270 observations per engine per sweep (30 questions in three languages, each run three times), a 50% mention rate carries a margin of at least six percentage points either way, so only larger changes count. Test a tactic the way Ahrefs tested schema: change half of a group of comparable pages, keep the other half as controls, and compare over 30 days. Annotate platform incidents such as the October ChatGPT tagging break, and compare season with season, never month with month.

## One sequence serves both sites, and it starts with plain HTML

The strategy can be generic because the mechanics are shared: both sites publish dated facts about places in one city, for locals and visitors who ask in several languages. It runs in seven steps ordered by strength of evidence and by durability, and the first two gate everything after them. The table states each step as a rule any site can follow, what the research team observed on the live mercaditos.app on 22 October 2026 ([mercaditos.app](https://mercaditos.app/berlin); [sitemap](https://mercaditos.app/sitemap.xml); [robots.txt](https://mercaditos.app/robots.txt)), and what changes for The Cultural Club, whose hosting and current pages this research did not examine.

| Step | Rule for any site | Mercaditos, observed 22 October 2026 | The Cultural Club |
|---|---|---|---|
| 1. Reachable | Admit every operator's search crawler and live fetcher; set training policy separately; keep CDN and firewall rules from challenging verified bots; get indexed in Google, Bing and Brave | robots.txt allows everything except `/api/`, with no Cloudflare in front. Requests with Bingbot's and Applebot's user agents got an uncached render taking 6.2–6.5 s, the path Copilot's and Siri's crawlers use | If served through Cloudflare, check AI Crawl Control first: blocking "Training" also blocks Googlebot, Bingbot and Applebot |
| 2. Readable | Every fact as visible text in the first HTML response, early and outside late-streamed blocks; real 404, 410 and 301 decided before streaming; `rel=canonical`; one crawlable URL per language with hreflang; semantic, labelled controls; filters as shareable GET URLs | Unknown URLs return 200 with noindex; `/.well-known/tdmrep.json` returns an HTML page with 200; no canonical, hreflang or JSON-LD on `/berlin`; one URL serves three languages by request header, so crawlers almost certainly see English only | Same rules; Catalan pages need Spanish and English versions to reach Google's Event results and English questions |
| 3. The record | One durable URL per entity, updated each edition, past editions archived; each fact with its year, a verified-on date, a named source and a status (announced, not announced, cancelled, postponed, ended); per-day hours with exceptions; comparison pages for cross-place questions; every language generated from one database | The new "not announced" status model (W2) is this rule; add per-day hours for 24, 25, 26 and 31 December and pages such as "open on 26 December" | Events expire within days, so evergreen hubs ("this weekend in Barcelona") carry lasting citations; set a policy for ended events |
| 4. Fresh | `lastmod` set to the real change time; IndexNow on create, update, cancel and remove; request indexing in Search Console; season pages live weeks ahead; honest `dateModified` and `eventStatus` | All 95 sitemap entries carry the generation timestamp, and they list locale-prefixed URLs that 307-redirect | Track the time from publishing an event to its first verified search-bot fetch |
| 5. Corroborated | Earn mentions where assistants already look (city and tourism listings, local press, YouTube, genuine community answers) with unique, quotable data; keep third-party records right; never manufacture mentions | berlin.de, visitBerlin and the Berlin press; a dated list of markets missing from the official list is a natural hook | Barcelona city listings and arts press; link ticketing partners' event pages so dates and prices agree |
| 6. Agent options | JSON-LD generated from the same row as the visible text; a read-only MCP server returning canonical URLs; llms.txt only if generated live; skip NLWeb, A2A and Markdown mirrors; watch WebMCP | Emit `Event` only when dates are announced and `Place` otherwise, with free-entry markup only on evidence, per the project's "unknown is not free" rule; the existing 2.7 KB llms.txt is harmless unless it starts carrying dates | Add `eventStatus`, sold-out `availability` and `performer`; an MCP server can report cancellations live |
| 7. Measured | Verified bot logs, AI referrals, Search Console and Bing reports, a repeated prompt panel scored for mentions and date accuracy, an optional app tracker | Extend `proxy.ts`, whose matcher skips `robots.txt`, `sitemap.xml` and `llms.txt`; keep Umami recording query strings; verify the site in Bing Webmaster Tools; take an October baseline, then sweep weekly from mid-November | A weekly panel all year, in Spanish, English and (to confirm) Catalan |

The order matters more than the list. Steps one and two hold the proven failures: agentready's experiment found that only blocking and JavaScript-hidden answers broke agents, AI crawlers in the 2024 log study hit missing pages on about a third of their fetches ([Vercel/MERJ](https://vercel.com/blog/the-rise-of-the-ai-crawler)), and a soft 404 titled "This-city-does-not-exist Markets" is exactly the page a guessing assistant could mistake for a real one. Steps three and four are where a places site wins or loses, because they decide whether the facts an assistant retrieves are complete and current. Step five compounds slowly, and step six is a set of cheap options whose payoff nobody has measured. Each later step is wasted if an earlier one fails.

The hardest call for Mercaditos is language. Today one URL serves English, German or Spanish depending on the visitor's `Accept-Language` header, and the response does not tell caches that it varies on that header, so crawlers that send no such header from US data centres almost certainly see only English. **Google's documented remedy is a crawlable URL per language with hreflang, which collides with the project's standing rule against a locale in the URL.** Keeping the rule has a concrete cost: AI Overviews cite German-language pages for about 90% of German questions and Spanish-language pages for about 83% of Spanish ones ([Temso](https://www.temso.ai/data/-Lost-in-Translation-How-AI-Models-Handle-Local-Language-Sources)), so a German or Spanish version that no crawler can see forfeits those questions to berlin.de, the German press and Spanish travel sites. Whether each language gets a path segment or a subdomain is a project choice; what the evidence requires is that each language has its own crawlable address. The decision belongs to the project owner, and it should be made before the season's pages are crawled.

The Cultural Club runs the same steps on a faster clock. Its events expire within days, so the crawl-recency measure matters more than any seasonal sweep, and lasting citations will go to evergreen hubs rather than single events. It needs an explicit policy for ended events (keep the page marked "ended", return 410, or redirect), because no framework or study says what assistants prefer. Its ticketed events already reach assistants through ticketing partners, so its pages should link the partner's event page and agree with its dates and prices. Catalan pages do not qualify for Google's Event results ([Google](https://developers.google.com/search/docs/appearance/structured-data/event)) and no study covers Catalan retrieval, so Spanish and English versions of each event are the hedge for search and visitors, with Catalan for locals.

## Conclusion

The evidence sorts the work by durability. Everything that serves every channel at once (reachable, server-rendered, correctly-statused, honestly-dated pages) kept its value through every platform change this research covered, while protocol-level bets aged in months: ChatGPT's plugins died, Atlas closed, agentready retired its own identifiers, and the MCP server-card path kept moving between drafts. For a small team that is the decisive filter. Spend on the substrate, and take protocol bets only when they fall out of the same database at little cost, as generated JSON-LD and a read-only MCP server do. The "agent-ready" and GEO industries sell a new layer on top of the web; the measurements describe AI search as ordinary search re-weighted toward pages that state current facts plainly.

For places and events, the edge is operational rather than technical. Assistants fail by omission and staleness, so the site that wins is the one that is right on a given date: verified each season, explicit about what is unknown, closed or cancelled, and consistent across languages. That is the project's existing scrape, resolve and curate discipline turned outward, and it lets the database do double duty, as the product and as the ground truth for scoring what assistants say about the niche. The first season of date-accuracy data will be the only benchmark that exists for this kind of question, which makes it worth more than any readiness score. It is also the part of this strategy The Cultural Club should copy as doctrine, without sharing any code.
